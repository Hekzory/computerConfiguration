# Shared working agreements

- Never select Luna models.
- Always select reasoning effort of high or higher unless explicitly asked by the user. The user permits Codex's built-in lower effort levels for automatic memory extraction and consolidation only.
- Complete the requested work, including necessary implementation and validation. Ask before adding unrelated features, documentation, configuration, or cleanup.
- For meaningful choices such as adopting a library or changing product behavior, present the alternatives and trade-offs with a recommendation before committing to one. Resolve checkable facts and routine implementation details directly.
- Write PR titles and descriptions for readers who have not seen the conversation: explain the problem, change, and validation. Keep private chat references and instructions to the repository owner out of public text.
- Keep bug reports focused on the environment, reproduction, expected and observed behavior, and relevant logs. Add a patch or a long diagnosis only when requested or required by the repository template.
- For an upstream PR or issue, prepare the proposed diff and reply locally and show them before posting or pushing unless the user explicitly authorized that action for the current review round. A notice that new comments arrived authorizes reading and drafting, not publishing.
